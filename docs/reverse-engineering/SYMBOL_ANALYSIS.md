# Symbol analysis — original Mac executable

Target: `A Story About My Uncle.app/Contents/MacOS/ASAMU` (build 1822049, x86_64 Mach-O, 67,378,284 bytes,
`LC_UUID` `9601348A-2FAC-3566-998D-B4114A14260B`; SHA-256 in [BINARY_ANALYSIS.md](BINARY_ANALYSIS.md)).

This file records **sanitized statistics and selected names** produced by `tools/asamu-symbols`. The full
machine-readable result is [`data/symbols/summary.json`](data/symbols/summary.json) (statistics, rule table,
native-class map, keyword counts, anchors — never the raw symbol list). Every number below is regenerated by
the commands in [Reproduce](#reproduce); the tables marked *generated* are pasted verbatim from
`asamu-symbols --markdown`.

Previous version of this file (manual `nm`, session 1): 53 `ASAMU` symbols, 0 `grapple`. Both numbers are
re-confirmed by the tool; the debug map adds 7 more symbols that come from the ASAMU module but do not carry
the name (see [ASAMU-specific natives](#asamu-specific-natives-complete-list)).

## Method

1. **Parse** the Mach-O directly with the `object` crate (no `nm` subprocess, so it runs on Windows/Linux too):
   every `nlist_64` entry of `LC_SYMTAB`, its section (`n_sect`), `N_EXT`/`N_PEXT`, and for undefined symbols
   the two-level-namespace library ordinal (`n_desc`), resolved against the `LC_LOAD_DYLIB` list.
   Kind: `text` (instruction section), `data`, `bss` (zero-fill: `__bss`, `__common`), `undefined`, `other`.
   `__TEXT,__const_coal` is flagged with instruction attributes by the old linker but only holds 12
   coalesced constants; it is counted as `data` so that `text` equals `nm`'s `T`+`t`.
2. **Demangle** Itanium names with `cpp_demangle` after removing exactly one Mach-O leading `_`
   (`__ZN5APawn11physWalkingEfi` → `APawn::physWalking(float, int)`). A second pass without parameters gives
   the qualified name used for grouping. The demangler runs under `catch_unwind` with a recursion limit and a
   16 KiB name cap, so hostile names can only fail.
3. **Debug map.** The executable still carries 400,188 STABS entries (`nm -a`; plain `nm` hides them):
   `N_SO`/`N_OSO` pairs name 1,330 compilation units / archive members and `N_FUN`/`N_STSYM`/`N_GSYM`
   entries list the functions and statics each one contributed. Each regular symbol is attributed to a
   unit by address (`N_FUN`, `N_STSYM`) or by name (`N_GSYM`): 134,634 of 135,093 symbols are attributed;
   the remaining 459 are the 450 imports, 7 crt/linker symbols (`start`, `__mh_execute_header`, `_NXArgc`,
   `_NXArgv`, `_environ`, `___progname`, `_pvars`) and 2 Scaleform function-local statics
   (`MovieDefImpl::GetFontResource(…)::fontlibKey`, `Render::HAL::Draw(…)::__FUNCTION__`) that have no
   `N_STSYM` entry. The stabs contain **absolute build-machine
   paths with third-party user and workspace names**; the tool reduces every path to a component label and a
   path relative to `Development/Src/` or `External/` before anything is stored or printed, and the
   published files contain no such paths (checked by a unit test and by `repo-hygiene`).
4. **Classify** with an ordered rule table (first match wins): specific *name* rules, then *provenance*
   (debug-map component), then *import* (dylib of an undefined symbol), then weak *convention* fallbacks.
   The rule table, with per-rule match counts, is generated from the code (below).
5. **Native registration recovery** from UE3 naming conventions (`AutoInitializeRegistrants<Pkg>`,
   `AutoGenerateNames<Pkg>`, `<Class>::PrivateStaticClass`, `G<pkg><Class>Natives`,
   `<Class>::exec<Func>(FFrame&, void*)`, `int<Class>exec<Func>`, `<PKG>_<Name>` FNames,
   `__GLOBAL__sub_I_<file>`), plus **decoding** of the `G…Natives` `FNativeFunctionLookup` tables
   (24-byte entries: name pointer + 16-byte pointer-to-member) and of the `int…` pointers, which are resolved
   back to symbols. Reads are bounds-checked against retained section bytes and capped by the next symbol.
6. **Keyword search** over CamelCase tokens of the qualified names (`Rope` matches `Ropes`, not `Property`);
   loose substring counts are reported alongside. Top names are filtered (no vtables, destructors,
   `DECLARE_CLASS` boilerplate, function-local statics) and ranked: core gameplay classes, then
   ASAMU/UDKBase/GameFramework, then Engine actor/object members.
7. **Anchors**: a curated list (our selection and rationale) resolved against the binary for address,
   signature and compilation unit; missing anchors would be reported (none are).

## Reproduce

```bash
# default discovery: ASAMU_ORIGINAL_DIR, ASAMU_STEAM_ROOT, then ~/Library/Application Support/Steam/...
cargo run -p asamu-symbols                                  # category overview
cargo run -p asamu-symbols -- --markdown                    # all tables in this file
cargo run -p asamu-symbols -- --json                        # full statistics JSON to stdout
cargo run -p asamu-symbols -- --write-summary docs/reverse-engineering/data/symbols/summary.json
cargo run -p asamu-symbols -- --check-summary docs/reverse-engineering/data/symbols/summary.json
cargo run -p asamu-symbols -- --search physFalling          # LOCAL ONLY, do not commit output
cargo run -p asamu-symbols -- --search Camera --category udk --limit 50
cargo test -p asamu-symbols                                 # real-binary tests skip without game data

# independent cross-check with Apple's nm
B="$ASAMU_ORIGINAL_DIR/A Story About My Uncle.app/Contents/MacOS/ASAMU"
nm "$B" | wc -l; nm -U "$B" | wc -l; nm -u "$B" | wc -l; nm -a "$B" | wc -l
nm "$B" | awk '{print $(NF-1)}' | sort | uniq -c | sort -rn
```

The summary is deterministic (sorted maps, integer arithmetic); `tests/real_binary.rs` fails if the
committed `summary.json` differs from a fresh run on a machine that has the game.

- `UTGame` is pure script on top of `UDKBase` natives, as in stock UDK. Three sources support this:
  - the binary has no `UTGame` registrant, natives table, class or FName (CONFIRMED);
  - `ASAMU/Config/DefaultEngine.ini` lists `+NonNativePackages=UTGame` under `[Engine.ScriptPackages]`
    and `+Package=UTGame` under `[Engine.StartupPackages]` (CONFIRMED by reading the config);
  - `NativePackages` names only `UDKBase` (CONFIRMED by reading the config).
- The movement core the script relies on is `APawn::performPhysics` and its `phys*` routines in
  `Engine/Src/UnPhysic.cpp`, with collision through `UWorld::MoveActor` / `SingleLineCheck`
  (`Engine/Src/UnLevAct.cpp`).

### TENTATIVE

- Whether the ASAMU pawn derives from `UDKPawn` (which would make the `AUDKPawn` overrides the live
  movement code) or from `GamePawn`/`Pawn` — decide from the script class hierarchy.
- Grapple is likely built from script `Trace` + velocity manipulation in `PHYS_Falling` (or a custom
  physics mode); PhysX constraints (`ARB_ConstraintActor`) are an alternative to rule out.
- The split between `FNativeFunctionLookup` tables and `int` registrations described above. The counts and
  the per-class breakdown are CONFIRMED; the interpretation (fixed-index natives versus name lookup) is
  TENTATIVE.
- Stock PhysX handles and constraints (`URB_Handle.GrabComponent`, `URB_ConstraintInstance`,
  `ARB_ConstraintActor`, `URB_Spring`) are the native building blocks a script grapple or rope could use
  if it is not purely trace- and velocity-based.
